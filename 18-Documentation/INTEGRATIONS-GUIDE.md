## Hosting setup (after approval)
- **Build command:** `npm ci && npm run build`. **Publish directory:** `02-Public-Website/dist`. **Node:** 20+.
- Set the env vars in the host dashboard. `dist/_headers` applies security headers and CSP on Netlify and Cloudflare Pages. On Vercel, port it to `vercel.json`.
- Protect preview deployments with a password until go-live.

## n8n intake workflow (built, inactive)
**File:** `12-Automations/n8n/rrs-intake.workflow.json`, regenerated by `npm run workflows`.
1. **Webhook** `POST /webhook/rrs-intake`. The response comes from the workflow. Set *Allowed Origins* to your real domain (the placeholder is `example-rrs-domain.com`).
2. **Validate & normalise.** A Code node runs the bundled `05-Lead-Research/intake/lead-intake.ts`, the same rules as the browser, the tests and the mock. It re-checks the honeypot and fill time, validates and normalises email, phone (E.164), website and domain, strips unknown fields, and builds `dedupe_key` + `lead_id`.
3. **Accepted?** → **Create/update CRM lead.** POST the lead record to `$env.RRS_CRM_WEBHOOK_URL`, with 3 retries. Upsert on `dedupe_key`, so a retried submission never creates a duplicate.
4. **Notify owner.** POST a one-line message to `$env.RRS_NOTIFY_WEBHOOK_URL` (Slack/Teams/email webhook).
5. **Responses.** Accepted → 200 `{ok, lead_id}`. Spam → 200 `{ok:true}` (silent, so bots learn nothing). Invalid → 422 `{ok:false, errors}`.

**To activate (after approval):**
- Import the JSON into n8n.
- Set both env vars on the n8n host. If your n8n blocks `$env` in nodes (`N8N_BLOCK_ENV_ACCESS_IN_NODE`), use n8n Variables instead.
- Set Allowed Origins.
- Run a test submission from a preview deploy, then activate.
- Set `FORM_ENDPOINT` on the website to the production webhook URL and rebuild.

**Status:** structure, wiring and embedded code are tested. It hasn't been imported into a live n8n yet. Review it there before activating.

**Research drafts:** `npm run snapshot:new -- lead.json` turns an accepted request into `05-Lead-Research/Research-Outputs/<business>-<date>.snapshot.json`. That folder is git-ignored because it holds personal details. Record evidence, then run `npm run snapshot:export -- <file>` for all six report formats.
The payload contract is in `02-Public-Website/src/lib/lead-payload.ts`.

## Search Console
Verify the domain property with a DNS TXT record, then submit `https://<domain>/sitemap.xml`. Watch Coverage and Enhancements (FAQ, Breadcrumbs). Setting `SITE_URL` to the real domain automatically removes the preview `noindex` and opens robots.txt.
